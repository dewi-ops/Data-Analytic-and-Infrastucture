## Data Infrastructure and Analysist

# Deskripsi Kasus
Sebuah instansi pendidikan memiliki data siswa yang berasal dari beberapa sekolah dengan format data yang
berbeda-beda, yaitu:
1. File CSV
2. File SQL Dump
3. File JSON
Sebagai seorang Data Engineer, Anda diminta untuk membangun sistem otomatisasi ETL (Extract, Transform, Load)
menggunakan Python di Google Colab.
Data hasil integrasi harus disimpan ke database SQLite dan dapat diproses secara otomatis menggunakan scheduler.
Dataset yang Disediakan
Mahasiswa diberikan 3 file berikut:
Nama File Format
siswa_sekolah_a.csv CSV
siswa_sekolah_b.sql SQL Dump
siswa_sekolah_c.json JSON

# Instruksi Praktik
A. Persiapan Environment
1. Gunakan Python pada:
o Google Colab
2. Install library yang dibutuhkan:
o pandas
o sqlite3
o schedule
o logging
o json
B. Proses EXTRACT (25%)
Buat fungsi extract untuk membaca seluruh dataset:
Ketentuan:
1. File CSV harus dapat dibaca dengan benar.
2. File JSON harus diparsing menjadi dataframe/tabular.
3. File SQL dump harus dapat diekstrak datanya menggunakan regex atau metode lain.
Output:
Setiap source menghasilkan dataframe.
Contoh:
df_csv
df_json
df_sql
C. Proses TRANSFORM (25%)
Lakukan transformasi agar seluruh dataset memiliki schema yang sama.
Schema Target
Kolom
nisn
nama
jenis_kelamin
tanggal_lahir
sekolah
alamat
jenjang
kota
status
Ketentuan Transformasi
1. Samakan nama kolom dari seluruh source.
2. Tambahkan:
o source_file
o created_at
3. Hapus duplicate berdasarkan:
o nisn
4. Lakukan validasi data kosong apabila diperlukan.
D. Proses LOAD ke SQLite (20%)
Buat database SQLite bernama:
warehouse_siswa.db
Buat tabel:
master_siswa
Ketentuan:
1. Gunakan:
o nisn sebagai PRIMARY KEY
2. Implementasikan:
o UPSERT / ON CONFLICT
3. Data hasil ETL harus tersimpan otomatis ke SQLite.
E. Scheduler ETL (15%)
Buat scheduler ETL otomatis menggunakan library:
schedule
Ketentuan:
1. Scheduler menjalankan proses ETL otomatis setiap:
o 1 menit (simulasi)
2. Scheduler harus berjalan terus menggunakan:
o while True
3. Tampilkan status scheduler di terminal/notebook.
Contoh:
Scheduler aktif...
ETL SUCCESS...
F. Logging dan Monitoring (10%)
Buat monitoring ETL menggunakan:
logging
Ketentuan:
1. Simpan log ke file:
etl_log.log
2. Log minimal mencatat:
• waktu ETL,
• source yang diproses,
• jumlah data,
• status sukses/gagal.
3. Mahasiswa harus dapat menampilkan isi log.
G. Simulasi Penambahan Data Baru (5%)
Lakukan simulasi penambahan data baru ke file CSV.
Ketentuan:
1. Tambahkan minimal 1 data baru.
2. Scheduler harus membaca data baru otomatis.
3. Data baru harus masuk ke SQLite tanpa manual insert.
